# 書類エンジン — 重説・マイソク（Office成果物生成）

> 実装: `hub_core/docgen.py` ／ 様式: `hub_core/templates/office/` ／ 作成: 2026-06-25

## 原則（なぜHTML自作をやめたか）

**重説・マイソクは実務でExcel/Word固定様式として作る。HTMLで近似を手書きしない。**

- 法定書面（重説）の**文体・注意書き・レイアウトは様式そのものの一部**。ゼロから生成すると法的に危険。
- だからExcel/Word成果物は、**空のWorkbookから作った独自原紙**または**保存済み本文とschema**から生成する。
- **他社の原紙や記入例（記入済み見本）を流用しない**。記入例を空白化する方式は、例示データ（抵当権・金額等）が残留し続けるため採用しない。

## 設計（収束した3点）

1. **(A) 独自Excel原紙** … blank workbookから生成し、named rangesへデータを入れる。
2. **(B) schema駆動のWord生成** … 保存済み本文と項目schemaから `.docx` を作る。
3. **(C) 持ち込み互換** … 利用者自身が権利を持つExcel様式は、旧ラベル配置の互換経路で差し替えられる。

> 想定ユーザー: 既存の不動産業務から移行する各社PCの利用者。あいのて = local Webエンジン＋既定原紙＋権利を持つ自社様式の持ち込み。

## マイソク（`fill_maisoku_xlsx`）

- 原紙: `build_maisoku_template.py --all` が `openpyxl.Workbook()` からA/C/Bの3原紙を新規生成する。
  - A `maisoku_a_standard_landscape.xlsx`: Excel標準A4横、通常出力の既定。
  - C `maisoku_c_fax_mono.xlsx`: 業者間FAX向けA4横、白黒。
  - B `maisoku_b_buyer_portrait.xlsx`: 買主向けA4縦。
- 値の契約: 編集可能な81項目すべてに `ms_<field>` のnamed rangeを一意に割り当てる。固定セル番地や第三者原紙の列配置を契約にしない。一部だけ定義された原紙は無言で項目を落とさず、明示エラーにする。
- 見た目の契約: `style_font_*` / `style_accent_*` のnamed rangesへ、利用会社の色・書体から導いたトークンを適用する。
- 取扱業者欄も `ms_company_*` / `ms_license` / `ms_staff` 等へ会社プロファイルを差し込む。原紙には実在会社・担当者・物件の値を置かない。
- 写真と間取りはdata URIのPNG/JPEG/WebPだけをデコードし、OOXML内部へ画像として埋め込む。URLやローカルpathを取得しない。
- 利用者が持ち込む既存Excelにnamed rangesが無い場合だけ、旧ラベル配置の互換経路を使う。出力時は対象シート1枚に絞り、外部relationship・macro・hidden sheetを除去する。
- 全原紙はA4、fit 1x1、明示print areaを持ち、`openpyxl.load_workbook(..., keep_links=False)` で再読込できることを検査する。
- `.xlsx` はそのまま出力できる。通常のPDF保存はHTMLプレビューをブラウザ印刷する。モバイルはA4 iframeを隠し、物件要点・全体確認/拡大・Excel保存・PDF保存（印刷）を表示する。
- Excel・ブラウザ印刷で、保存版の `company_profile_hash` が指す当時の会社色・書体を使う。現在の会社設定で過去書類を塗り替えない。
- 必要表示事項が不足している成果物は、出力を400で止めず、紙面上に「下書き」と明記する。完成扱いにはしない。

## 重説（`build_juusetsu_docx`）

- `deal_type` で売買/賃貸を切り替える（**項目体系が別物**）。保存済み本文のWord出力は `build_md_docx`、schemaからの下書き生成は `build_juusetsu_docx` が担う。
- 項目体系の正本: `hub_core/templates/office/juusetsu_schema.json`。Workflow（国交省標準様式＋建物賃貸様式の構造抽出＋35条法定事項調査＋敵対的完全性ループ）で確定。**売買=baibai(29章213項目) / 賃貸=chintai(27章129項目)**。
- `juusetsu_sections(deal_type)` が schema を読み (sections, key) を返す。`_clean_item` で検証エージェントの註記括弧を除去しフォーム向けに整える。
- 本文末尾に注意書き（各欄は登記簿・公的資料・現地で確認、宅地建物取引士が宅地建物取引士証を提示して記名し交付、最終責任は記名士に帰属）を必ず付す。
- 災害リスク欄は、明示設定したloopback/HTTPSの `juusetsu-hazard-v1` へ物件住所をPOSTし、土砂警戒区域、津波警戒区域、造成宅地防災区域、水害ハザードマップの洪水・内水・高潮を別行で受ける。
- 各行のstatus、根拠条項、都道府県市町村原典、版、確認日、document digest、確認先を検証して決定論的に差し込む。`NEEDS_PRIMARY_SOURCE`、未接続、契約不一致は値を推測せず空欄＋要確認にする。
- A33/A40/A54、大規模盛土、ハザードポータル図版を法定根拠に流用しない。PRSは下書き支援であり、原典確認と宅建士本人の記名確定を代替しない。
- `.docx` はそのまま出力できる。通常のPDF保存はブラウザ印刷を使う。

## PDF化（`office_to_pdf` / `_find_soffice`）

- 通常起動・通常回帰は `RI_HUB_DISABLE_SOFFICE=1` を固定し、 `_find_soffice()` は探索前に `None` を返す。
- LibreOffice実変換は、明示的に許可された単発・非並列実行だけに隔離し、通常の機械検証やclean-room検証では起動しない。
- ブラウザ印刷によるPDF保存はLibreOfficeを必要としない。
- 依存: `openpyxl`（xlsx）・`Pillow`（埋込画像）・`python-docx`（docx）。検証済み版は `requirements-office.txt` に固定する。
